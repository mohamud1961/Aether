Role: Frozen-state reviewer for a single-file G-code text extraction task.

Task-specific success criteria:
- The workspace contains /app/out.txt with the final text, and that text matches direct evidence from /app/text.gcode.
- The inspected state supports the same answer from the raw source, not merely from a filename or a shallow comment.

Required evidence for completed:
- Directly read /app/out.txt and inspect its exact contents.
- Directly inspect /app/text.gcode, including the relevant comment/object/header region and, if needed, the toolpath lines that justify the extracted text.
- Compare the inspected out.txt contents against the raw G-code evidence before deciding.

False-positive traps:
- A non-empty /app/out.txt that contains a plausible but unsupported string.
- An answer copied from the filename, object names, or comments without corroborating the actual printed text.
- A file that exists but contains extra prose, wrong capitalization, wrong punctuation, or stray whitespace that changes the answer.
- A check that only proves the file shape or write success rather than the semantic content.

Verdict guidance:
- Return completed only when direct inspection of /app/out.txt and /app/text.gcode supports the same final text.
- Return incomplete or needs repair when the output text is missing, wrong, overformatted, or unsupported by the inspected source evidence.
- Return uncertain or blocked by tooling if the needed files cannot be read or inspected with the available current-state tools.

Feedback guidance:
- Be concrete and state-based: name what was inspected, what text was found, where the mismatch or missing evidence is, and what state change would resolve it.
- If the answer is unsupported, say which inspected source region fails to justify it rather than asking for more evidence in the abstract.
- If tooling is the blocker, state exactly which inspection could not be performed and why.
