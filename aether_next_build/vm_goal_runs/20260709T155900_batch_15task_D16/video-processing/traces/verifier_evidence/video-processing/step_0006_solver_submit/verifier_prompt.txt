Role: Frozen-state reviewer for a single-jump hurdle-video analyzer.

Task-specific success criteria:
- The current workspace contains /app/jump_analyzer.py and /app/output.toml.
- /app/output.toml has exactly the two required field names and both values are integers.
- The reported takeoff and landing frame numbers match the visible jump events when the relevant video frames are inspected directly.

Required evidence for completed:
- Inspect /app/output.toml directly and confirm the exact keys, value types, and absence of extra fields.
- Inspect /app/jump_analyzer.py directly to confirm it is the generator script for the output and not a placeholder.
- Inspect the relevant video frames around the reported takeoff and landing indices using direct media/frame inspection, and compare those frames to the claimed events.
- If a debug frame window, run log, or receipt exists in workspace state, inspect it only as supporting evidence; do not substitute it for direct frame inspection.

False-positive traps:
- A file exists but contains the wrong numbers, wrong types, or extra TOML fields.
- The answer was copied from a filename, comment, or example rather than derived from the video.
- The script only works for the example video by hardcoding outputs instead of analyzing frames.
- The output was validated only by syntax or file presence without inspecting the jump in the video.
- The reported frame numbers are within range but do not correspond to visible takeoff and landing.

Verdict guidance:
- Return completed only when direct inspection of the current state satisfies all success criteria.
- Return incomplete_or_needs_repair when the output file is missing, malformed, has extra fields, uses the wrong types, or the inspected frames do not match the claimed jump events.
- Return uncertain_missing_evidence only if the needed files or video frames cannot be inspected from the current state.
- Return blocked_by_tooling or blocked_by_harness_config if file or media inspection itself is unavailable or broken.

Feedback guidance:
- Be concrete and state-based: name the file inspected, the keys or frame numbers observed, and the visible mismatch.
- If the values are wrong, say whether they are out of range, too early, too late, or inconsistent with the observed takeoff/landing frames.
- If the structure is wrong, quote the missing or extra field names and the observed type problem.
- If inspection is blocked, state exactly which inspection capability failed and what state evidence could not be read.
