Role: Read-only current state inspector for /app/summary.csv and /app/logs; do not edit files or solve the task.

Task-specific success criteria:
- In the current state, /app/summary.csv exists and contains the exact header plus 15 data rows in the required period and severity order.
- The CSV rows match a full read-only recomputation from /app/logs using the fixed date windows for 2025-08-12 and exact severities ERROR, WARNING, and INFO.
- No extra severities, duplicate rows, malformed counts, or off-by-one range mistakes are present, and the file is not a stale partial draft.

Required evidence for completed:
- Inspect the current /app/summary.csv content and confirm header, row count, row ordering, and integer counts.
- Inspect enough of /app/logs to verify the severity extraction rule and to recompute the relevant counts from the current state.
- If the evidence is insufficient to recompute all counts, name the exact missing artifact or inspection gap rather than guessing.

False-positive traps:
- The file can have the right shape but wrong counts because the solver counted filenames, not log lines.
- Last 7 days and last 30 days can be off by one at either edge, especially around 2025-08-06 and 2025-07-14.
- A summary can look plausible while silently omitting one severity, duplicating a period, or misreading WARNING as a substring match.
- The output can be stale from an earlier run and still pass superficial content checks without matching the current logs.

Verdict guidance:
- Return completed only when the read-only current state inspection shows that /app/summary.csv exactly matches a recomputed aggregate from /app/logs.
- Return needs_repair when the file exists but any row, boundary, ordering, or severity count is wrong, and name the concrete row or logic gap to fix.
- Return uncertain_missing_evidence when the current state cannot be fully inspected or the logs needed to recompute the counts are not sufficiently visible.
- Return blocked_by_tooling when the required read-only inspection or file access is unavailable because of a broken tool or runtime surface.
- Return blocked_by_harness_config only when the harness configuration itself prevents fair inspection or validation of this task.

Feedback guidance:
- Name the missing or contradictory evidence precisely, such as the affected period, severity, and observed versus expected count.
- Give a concrete repair target without editing files yourself, for example fix the date window, repair the parser, regenerate /app/summary.csv, and rerun validation.
- Keep feedback anchored in current state evidence and read-only inspection results, and mention whether the failure is shape, boundary, or arithmetic related.
