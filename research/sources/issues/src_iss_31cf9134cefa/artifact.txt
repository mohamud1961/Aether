Please describe. LangChain4j currently provides powerful agentic abstractions (sequential, conditional, loop planners, MCP tool calling, etc.), but there is no built-in mechanism for durably executing long-lived agent tasks that survive process restarts, support pause/resume with human-in-the-loop, or provide automatic retry with exponential backoff. When building production agentic applications, developers need: Crash recovery — if the JVM restarts mid-workflow, the agent should resume from its last checkpoint rather than re-execute from scratch. Pause / Resume — human-in-the-loop patterns (e.g. approval gates) require explicitly pausing the workflow, persisting state, and resuming after external input. Automatic retry — transient failures in tool calls (network, rate-limits) should be retried with configurable backoff, not silently swallowed. Observability — a full event journal of what each agent did, when it retried, when it paused, and what the final outcome was. Cancel safety — cancelling a running task must not corrupt persisted state, even when cancel races with natural completion. Without these capabilities, developers are forced to build ad-hoc durability layers on top of LangChain4j, leading to fragile and inconsistent implementations. Describe the solution you'd like A new experimental module ( langchain4j-experimental-durable-tasks ) that provides a complete durable task execution layer: Core components Component Description LongLivedTaskService Central orchestrator — start, cancel, pause, resume, retry, query tasks TaskExecutionStore (interface) SPI for durable persistence of task metadata, event journals, and checkpoints InMemoryTaskExecutionStore In-memory implementation for testing and development FileTaskExecutionStore File-based implementation for single-node production use TaskMetadata Mutable holder for task identity, status, timestamps, labels TaskHandle Caller-facing handle with awaitResult() , cancel() , status() TaskConfiguration Per-task config: agent name, retry policy, checkpoint policy, timeout, labels RetryPolicy Configurable retry with max retries, initial delay, backoff multiplier, retryable exception filter CheckpointPolicy NONE , AFTER_EACH_AGENT , AFTER_ROOT_CALL — controls when scope-aware checkpoints are taken JournalingAgentListener AgentListener implementation that records all agent invocations as structured events ReplayingPlanner On resume, replays completed invocations from the journal to fast-forward agent state CheckpointManager Serializes AgenticScope state into durable checkpoints TaskPausedException Thrown by agents to signal pause (e.g. waiting for human input) Task lifecycle PENDING → RUNNING → COMPLETED → PAUSED → (resume) → RUNNING → RETRYING → RUNNING (next attempt) → FAILED → (resume) → RUNNING → CANCELLED Key design decisions Store-atomic compare-and-set — All status transitions go through TaskExecutionStore.compareAndSetStatus() , which atomically loads persisted metadata, checks expected status, transitions, and saves. This prevents the race where cancel and completion operate on different deserialized metadata instances. Scope-aware checkpoints via AgentListener — Checkpoints with serialized AgenticScope state are created by JournalingAgentListener.beforeAgenticScopeDestroyed() , not by the service's completion path. This ensures checkpoint scope data is never null when it matters. Event journal as append-only log — All lifecycle events (start, agent invocations, retries, pauses, cancellations, completions, failures) are recorded in an ordered, immutable journal per task. Pluggable store SPI — The TaskExecutionStore interface allows database-backed implementations for multi-node production deployments. Not suitable for teams that want to stay within the LangChain4j ecosystem. Manual checkpoint files — fragile, no atomic guarantees, no event journaling, no standard pause/resume protocol. Spring Batch — oriented toward batch data processing, not agentic workflows with dynamic branching and human-in-the-loop. Additional context This module is placed under experimental/ to signal that the API may evolve. It builds on existing LangChain4j abstractions ( AgentListener , AgenticScope , planner interfaces) and does not introduce external dependencies beyond Jackson for JSON serialization.
