This causes agents to silently resume with incomplete or corrupted state, which is particularly dangerous in long-running stateful workflows where the agent doesn't immediately detect the data loss. When a checkpoint contains a custom type that the deserializer doesn't recognize (e.g., a third-party library's class or a type defined in code that was refactored), the current behavior is: The type annotation fails to deserialize JsonPlusSerializer returns the raw dict instead of the original object The graph resumes execution with a dict where it expects a typed object Downstream nodes fail at runtime or produce incorrect results This violates the contract of durable execution: "resume from exactly where they left off" only works if the state is actually preserved. Why this matters LangGraph's core value proposition is durability — agents should survive restarts without losing context. Silent state corruption undermines this guarantee. When an agent resumes with a malformed checkpoint, bugs can cascade through multiple execution steps before surfacing, making them harder to diagnose. Current behavior In JsonPlusSerializer.loads() , when _deserialize_value() encounters a type it can't handle: # langgraph/checkpoint/serde/types.py # Returns the raw dict silently return value # Should raise instead Test case: from langgraph . checkpoint . serde . types import JsonPlusSerializer class CustomType : def __init__ ( self , data ): self . data = data serializer = JsonPlusSerializer () original_state = { "item" : CustomType ( "test_data" )} serialized = serializer . dumps ( original_state ) deserialized = serializer . loads ( serialized ) # Current: deserialized["item"] is a dict, not CustomType # Expected: raise DeserializationError with clear message about missing type handler assert isinstance ( deserialized [ "item" ], CustomType ) # Fails silently Expected behavior JsonPlusSerializer should raise a clear, actionable error when it encounters a type it cannot deserialize. The error should include: The type name that failed The checkpoint ID or context where this occurred A suggestion to register the type or update the serializer This gives users immediate feedback during checkpoint resume rather than silent failures downstream. Implementation direction Modify the fallback path in _deserialize_value() to raise DeserializationError instead of returning the raw dict. Add a type registry mechanism (similar to JsonPlusSerializer.register_type() ) so users can explicitly register custom types for checkpoint serialization.
