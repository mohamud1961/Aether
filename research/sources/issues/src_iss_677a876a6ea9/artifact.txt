Issues that need to be triaged by the triage automation. Description sotokisehiro opened on Feb 1, 2026 Issue body actions What happened? The Gemini CLI takes several minutes to finish initialization after startup on Linux systems (specifically tested on Debian 12 and Ubuntu 22.04). The delay occurs after the logo is displayed but before the context information appears. Root Cause Investigation: The issue is caused by the CLI attempting to download the ripgrep binary to ~/.gemini/bin/rg during the initialization phase. In the affected environments, ~/.gemini/bin/rg does not exist, and the download process seems to hang or take an excessively long time. Manually installing ripgrep via apt (providing /usr/bin/rg) does not resolve the issue because the CLI strictly looks for the binary in its internal bin directory. Adding "useRipgrep": false to ~/.gemini/settings.json bypasses the ripgrep initialization and resolves the slow startup immediately. What did you expect to happen? The CLI should initialize within a few seconds. If a required binary is missing, the download should be handled gracefully (e.g., with a progress indicator) or should not block the entire startup process for minutes. (Improvement) The CLI should consider using the system-installed ripgrep if available.
