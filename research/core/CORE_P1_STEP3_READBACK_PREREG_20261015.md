# P1 step 3 — fresh tasks, baseline vs read-back (pre-registration, 2026-10-15)

Status: **SEALED by Claude before any step-3 model call.** Authority: the principal's "go, do it all" (2026-10-15), after
the cost discussion (GLM first, about $2–3; GPT-6-Luna only if GLM holds).

## Question

The P1 probes showed that GLM recognises a format error in its own file when asked to read the file by the task's
own definition (18/21) and rarely when asked to check generically (4/21). Both reviews asked the next question:
**can the solver choose that comparison itself, with no hint about the mistake, and turn it into a correct file?**

## The lever (one change from the baseline, flag-gated)

`--core-readback on` (commit `564472446`): one paragraph in the solver's system prompt (`tools.READBACK_DOC`):
read each delivered file back from disk and interpret it as the task defines it; quote the defining words per
column/field/segment; a comparison with the variable that wrote the file does not count; where the task specifies
a format, source or procedure exactly, follow it over library, domain or example conventions; fix mismatches. It
names no task, file or error. The baseline prompt is byte-identical when off (tested).

**Prior failures this must beat** (recorded honestly): the finish receipt (S6, 0/18 corrections), the generic
self-check (N1), the requirement ledger and self-qualified checks (N2/Q1) all failed to cut wrong finishes. The
difference claimed here is the instruction to *interpret the file by the task's definition*, which is what moved
the probes. The honest prior is that it fails like the others.

## Fresh tasks (`eval_suite/fresh_p1/`, generated by `generate.py`, never seen by any run)

Written by Claude from scratch; no benchmark task, file or name is reused. Graders are validated locally: a correct
output passes and the convention-trap output fails, for all six (12/12 checks).

| Task | Kind | Convention that the task's words contradict |
|---|---|---|
| arborescence-dst-first | trap | library edge tuples are (src, dst); the task's format is `dst,src` |
| parcel-centroids | trap | GeoJSON and planar geometry are (lon, lat) / (x, y); the task asks for `lat,lon` |
| account-balances | trap | a default CSV reader turns ids like `000417`, `12E3` into numbers |
| release-manifest-exact | trap | version tags are usually normalized; the task asks for the recorded tag exactly |
| arborescence-src-first | control | the task's format is the library order `src,dst` |
| release-manifest-normalized | control | the task asks for the normalized form (the convention) |

## Design

- Route: as B1 (`run_screen.py`, suite tb21, local task base, GLM, 4 parallel rows, each task's 900 s timeout,
  graders run by Harbor after the agent ends). Baseline arm `coreb1` = B1's flags; lever arm `rb1` = `coreb1` +
  `--core-readback on`.
- **Phase 0 (free):** oracle rows (no model) for all six tasks: each must build and pass its own grader.
- **Phase A (reproduction):** baseline, 3 episodes × 6 tasks = 18 rows. A trap task **qualifies** only if ≥ 2 of 3
  baseline rows fail **because of the trap** (hand-audited from the delivered file). Non-qualifying traps are
  reported and dropped, never re-tuned. Controls go forward if baseline passes ≥ 2/3.
- **Phase B (lever):** `rb1`, 3 episodes on each qualifying trap and both controls. Phase A rows are the baseline.
- If no trap qualifies, Phase B is not run and the result is "the failure did not reproduce on fresh tasks".

## Predictions (recorded before any row)

- **S3-P1 (primary):** on qualifying traps, `rb1` passes ≥ `coreb1` passes + ⌈n/3⌉ (n = rows per arm), i.e. at
  least one extra pass per qualifying task on average. Falsifier: any smaller gain.
- **S3-P2 (mechanism):** in ≥ half of `rb1` trap rows, the trace shows the delivered file read back and
  interpreted by the task's own definition (hand audit). Recognition and successful repair are counted separately.
- **S3-P3 (harm):** controls: `rb1` passes ≥ `coreb1` passes (0 regressions); timeouts `rb1` ≤ `coreb1` + 1.
- **S3-P4 (cost):** `rb1` mean cost per row ≤ 1.3 × `coreb1`.
- Sample sizes are tiny (3 episodes per cell). Whatever the outcome, it is exploratory; no promotion to a Core
  default without a larger sealed confirmation.
