# Deep Synthesis: Source-System Dossiers

Use this skill when a source-visible system needs its own dossier so the
mechanism and failure work does not stay flat.

## Trigger

Use when a source system materially shapes mechanism, failure, or eval claims.

## Inputs

Bring:

- source excerpts or architectural notes;
- trajectory links or behavioral reconstruction notes;
- the current mechanism or failure lane focus;
- contradictions or open questions about the system;
- any coverage gaps that keep the source picture partial.

## Workflow

1. Record the architectural core.
2. Separate tool calling, workflow doctrine, state, recovery, and verification.
3. Note what is directly source-backed and what is still inferred.
4. Preserve contradictions rather than smoothing them out.
5. Keep the dossier useful for downstream wave synthesis.

## Outputs

The dossier should summarize:

- source scope;
- architectural core;
- tool calling and execution;
- workflow and control doctrine;
- context and state model;
- memory or persistence model;
- verification and completion;
- recovery and resumability;
- environment and permissions;
- relevant trajectory links or behavioral caveats.

## Validation Checklist

- the dossier reaches architectural depth, not just a file list;
- source-backed claims stay source-backed;
- archive-only hints do not silently become facts;
- the dossier can support later mechanism or failure work;
- unresolved contradictions remain visible.

## What Not To Do

- do not fake source coverage for a system that is only behaviorally visible;
- do not turn a dossier into a summary note;
- do not use archive captures as if they were the system itself;
- do not hide limits on source visibility.
