01 / THE PROJECT

Build the computer around the model.

Aether is designed as an extensible computer for AI agents. The model chooses the approach and decides what it needs next. The surrounding system supplies tools, context, continuity, recovery and bounded access to a working environment.

The distinctive question is not whether agents should use tools. It is how much hidden decision-making the runtime should impose, and whether a model can create and reuse capabilities without losing the evidence needed to understand what happened.

For nine months, I have developed and funded the work independently through architecture, implementation, evaluation, failure analysis and redesign. The next phase is a controlled research programme, not a promise that the hypothesis is already correct.

PUBLIC POSITION

Ambition with a boundary.

Aether is not presented here as benchmark-wide superiority, a universal safety guarantee or a finished product. Those are claims the evidence does not currently support.

02 / HOW I WORK

Make the failures useful.

The project treats a task result, a verifier decision and a trace as different kinds of evidence. A grader can accept an artifact while the internal review path still blocks. A valid reward can sit beside an invalid measurement. The job is to preserve those distinctions long enough to learn from them.

That means freezing source and evaluation conditions, keeping provider and environment failures separate from capability failures, and publishing limitations alongside successful outcomes. Aether's design target is stronger agency inside explicit boundaries, with the cost of the full system visible.

THE THESIS

Better model, better agent.

The relationship should be measured under matched conditions rather than assumed from a compelling demo.

03 / WHAT COMES NEXT

Turn the idea into inspectable evidence.

The first funded period is three months. It will establish a reproducible baseline, run fair comparisons, test mechanisms separately and publish what survives.

01 / ESTABLISH

Freeze the question.

Define tasks, environments, budgets, validity rules and independent grading before the comparison.

02 / COMPARE

Measure the whole loop.

Count tool creation, recovery, review, latency and spend alongside completed task outcomes.

03 / PUBLISH

Keep the limits visible.

Release methods, results and failures where licensing, privacy and source custody allow.
