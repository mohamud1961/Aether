- summary: Independently inspected AHP and baseline TerminalBench/custom run artifacts. AHP is the same Aether-2 core with a startup-generated task-local context pack, completion contract, verifier payload, and reduced tool set. It does not change the base system prompt in the inspected runs. Evidence shows one real probabilistic solve-rate advantage on log-summary-date-ranges, consistent efficiency improvements on many passing tasks, and better premature-completion discipline on some capability-ceiling tasks. It does not overcome domain/tooling capability ceilings or grading-boundary failures.
- observations: TerminalBench model-backed A/B roots exist under tracking/local_runs/tbench_ahp_ab. The smoke git-leak-recovery row passed in both conditions, with AHP using fewer calls. The Stage 2D custom A/B passed in both conditions on all four custom rows, so it had no solve-rate headroom. The TerminalBench diverse/sweetspot set shows log-summary-date-ranges baseline 0.0 and AHP 1.0 in the first paired run; reproducibility logs later show baseline 1/4 and AHP 3/4 in a paired N=4 set. On log-summary, AHP froze exact date/reference/severity/row-order requirements and the downstream model produced the official-passing CSV in 3/4 paired AHP runs. The one paired AHP failure produced zeros despite the same contract, so the effect is probabilistic, not deterministic. On financial-document-processor, build-cython-ext, and build-pmars, AHP produced completion precheck rejections and ended with implicit_stop instead of false task_done, but official reward remained 0.0. Verifier_clean stayed false with three verification rounds in both baseline and AHP across inspected TerminalBench runs, so verification is a base-harness behavior and was not made clean by AHP.
- inference: AHP's current addressable surface is success-contract anchoring, exact-output/format/date-boundary discipline, tool-attention reduction, and completion honesty. It is not a broad solver upgrade. The startup model's best contracts are useful when the task is within the mini model's capability and failure comes from imprecise requirements. It does not fix capability-ceiling tasks, service/fresh-container grading boundary issues, or missing benchmark runtime assets.
