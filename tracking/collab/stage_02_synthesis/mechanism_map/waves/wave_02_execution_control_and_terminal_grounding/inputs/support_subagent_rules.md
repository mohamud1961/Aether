# Wave 02 Support Sub-Agent Rules

Use this addendum when a main follow-up analyst wants bounded support help.

## Core Mandate: Context Compaction

- **The primary goal of sub-agents is context compaction.**
- They exist to collect, filter, and organize context for the main agent so that the main agent can fit necessary evidence into its context window.
- **Support sub-agents DO NOT do the main agent's task.** They are researchers and summarizers, not synthesizers and decision-makers.
- Main agents should proactively spin up sub-agents for **very large and lengthy tasks** (e.g., examining hundreds of logs, deep codebase scans, or massive data matrices) that are tedious or would overwhelm a single context window.

## How to Prompt a Sub-Agent Excellently

When you (the main agent) spin up a sub-agent, you must provide a highly specific, excellent prompt:

- **Be exact about the scope:** Tell the sub-agent exactly which directories, files, or logs to look at. Provide boundaries so it knows when to stop.
- **Define the exact output format:** Instruct the sub-agent to produce a structured file (like a markdown matrix, checklist, or JSON) rather than an open-ended narrative.
- **Set clear behavioral boundaries:** Explicitly tell the sub-agent what *not* to do (e.g., "Do not synthesize these findings or make architecture decisions; just tell me what functions exist and where").
- **Require saved artifacts:** The prompt must instruct the sub-agent to save its output to an explicit artifact file and return the file path to you so you can read it.

## What support sub-agents are for

- Context compaction for large-scale unstructured evidence
- Run inventory checks
- Archive triage
- Per-run table building
- Source-file identification
- Source-link gathering
- Compact comparison matrices
- Bounded raw-evidence extraction

## What support sub-agents are not for

- Doing the main agent's assigned task
- Writing the main lane follow-up synthesis
- Deciding final promoted mechanism families
- Making final artifact-level claims on their own
- Replacing contradiction review or principal synthesis

## Required Output Rule

- Every support sub-agent output must be saved as an explicit artifact under:
  - `tracking/collab/stage_02_synthesis/mechanism_map/waves/wave_02_execution_control_and_terminal_grounding/outputs/`
- Use clear names such as:
  - `trajectory_support_run_inventory.md`
  - `trajectory_support_pass_fail_matrix.md`
  - `codebase_support_claw_code_map.md`
  - `codebase_support_src_cod_triage.md`

## Main-agent Responsibility

- The main follow-up analyst must:
  - initiate the sub-agent with a precise, excellent prompt
  - read the support artifacts generated by the sub-agent
  - cite the support artifacts explicitly in its final output
  - decide what the evidence means
  - write the actual follow-up synthesis

## Status Rule

- Support artifacts are context-gathering support only.
- They are not final evidence claims by themselves.
- A support artifact can strengthen a lane, but it cannot close the lane on its own.
